# Lenga Maps

## Production commit messages

Vercel displays the subject of the commit on `main` for each production deployment. Write that subject as a short, direct description of the change shipped. Name the feature, workflow, or provider involved and say what changed. For example:

- Route mobile money through Lipila and card payments through Lenco
- Find company emails from prospects’ own websites

When merging a pull request to `main`, use a squash merge with an explicit commit subject. Replace autogenerated subjects such as “Merge pull request #123” and avoid subjects such as “Fix issues” or “Update files.” Use the commit body for additional changes or verification details. If a squash merge is unavailable, set the final commit subject explicitly.

## Production-only deployments

The user requires production deployments only. Run checks locally or in CI and push the verified commit directly to `main` when authorized. Vercel builds production from `main`. Keep preview deployments disabled on the personal Vercel project that serves `www.lengamaps.com`. Verify that Vercel reports the production commit as Ready and share the production deployment link.
